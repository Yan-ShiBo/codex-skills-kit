# Persistent Task State

Use an existing task note when available. Create a concise plan only when the user requests one or continuity across sessions needs it. Tool-call count alone does not justify planning files.

Record the goal, current decisions, unresolved dependencies, verification evidence, and next action in one file. Split findings or progress into separate files only when their size makes the plan hard to use. Use the project's established notes location or a task-specific temporary directory; create files in the repository only when they belong to the deliverable.

Update at meaningful checkpoints or before a handoff. Re-read when resuming or when the goal/state is uncertain, not before every tool call. When a failure repeats, use the evidence to choose a different approach or report the actual blocker; no fixed retry quota is required.

Finish when the requested outcome and relevant checks are complete. Do not introduce stop hooks, mandatory templates, or additional work merely to make a checklist look complete.
